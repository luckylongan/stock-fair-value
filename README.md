# 幾塊你要買？

用八種常見的估價法計算台股（上市／上櫃）的合理價位，資料每個交易日自動從
臺灣證券交易所與證券櫃檯買賣中心抓取。純靜態網站，可直接放在 GitHub Pages 上。

**八種估價法**：本益比法（年化 EPS） ｜ 月營收動能法 ｜ PEG ｜ ROE 法 ｜ 股價淨值比法（P/B） ｜ 股價營收比（P/S） ｜ 股利法 ｜ 本益比法（近四季 EPS）

---

## 一、放上 GitHub 並開站

### 1. 建立 GitHub repo

到 <https://github.com/new> 建一個 repo。**名稱請用英文**（例如 `stock-fair-value`），
中文名稱在網址上會被編碼成亂碼。可以是 Public 或 Private，兩者都能開 Pages。
不要勾選 "Add a README file"。

### 2. 推上去

在專案資料夾執行（把網址換成你自己的 repo）：

```bash
git remote add origin https://github.com/<你的帳號>/stock-fair-value.git && git branch -M main && git push -u origin main
```

### 3. 開啟 GitHub Pages

到 repo 的 **Settings → Pages**，把 **Source** 選成 **GitHub Actions**（不是 Deploy from a branch）。

### 4. 給 Actions 寫入權限

到 **Settings → Actions → General**，捲到最下面的 **Workflow permissions**，
選 **Read and write permissions** 後按 Save。

這一步是必要的：每天更新完股價資料後，workflow 需要把 `data/` 的結果 commit 回 repo。

### 5. 跑第一次

到 **Actions** 分頁 → 左邊選「更新股價資料並部署」→ 右邊 **Run workflow**。
第一次可以勾選 `rebuild_bands` 一併重建近 5 年評價區間（約 5 分鐘）。

跑完後網站就在：

```
https://<你的帳號>.github.io/stock-fair-value/
```

之後每個交易日 **台北時間 15:20** 會自動更新資料並重新部署，不需要再手動操作。

## 二、資料怎麼來的

| 資料 | 來源 | 更新時機 |
| --- | --- | --- |
| 上市股價、本益比、股價淨值比、殖利率 | 證交所 `BWIBBU_d` | 每交易日 15:20（台北） |
| 上櫃股價、本益比、股價淨值比、殖利率 | 櫃買中心 OpenAPI | 每交易日 15:20（台北） |
| 近 5 年評價區間（P20/P50/P80） | 證交所歷史快照 | 手動觸發或每月 |
| 除權配股事件（攤薄修正用） | 證交所 TWT48U／TWT49U、櫃買中心 | 每交易日累積 |
| 季報累計每股盈餘／營收／淨利 | 證交所、櫃買中心、公開資訊觀測站 | 每交易日累積 |
| 每月營業收入 | 證交所 `t187ap05_L`、櫃買中心 | 每交易日 |

估價需要的每股數字，都由上面四個公開數字推算：

```
每股盈餘 EPS  = 收盤價 ÷ 本益比          （近四季）
每股淨值 BVPS = 收盤價 ÷ 股價淨值比       （最近一季）
股東權益報酬率 ROE = EPS ÷ BVPS = 股價淨值比 ÷ 本益比
每股現金股利 DPS = 收盤價 × 現金殖利率     （近一年）
```

### 除權配股的攤薄修正

交易所公布的本益比與股價淨值比，在除權當天是拿**已經稀釋的股價**除以**還沒按新股本
重算的每股盈餘**。實測倫飛 2364、華友聯 1436、豐藝 6189，除權日的本益比與股價淨值比
都隨股價跳空 20~30%，而反推出的每股盈餘一動也沒動：

```
倫飛 2364  8/27 → 8/28（除權配股 30%）
  收盤價   99.30 → 77.50   (−22.0%)
  本益比   24.95 → 19.47   (−22.0%)   ← 跟著股價跳空
  推算 EPS  3.98 →  3.98   (不變)     ← 沒有攤薄
```

交易所在除權息預告表裡揭露的「申報每股淨值」也證實了這點：根基 2546 於 2026-08-10
配股 12%，申報每股淨值仍是 50.33（未攤薄），而非 44.94。

若直接採用，本益比法、股價淨值比法、ROE 法的合理價會一併高估，幅度約等於配股率，
並持續到下一次財報更新。因此 `scripts/fetch_exrights.py` 每天累積配股事件，前端對
「除權日晚於財報基準季季末」的個股，把 EPS 與每股淨值除以 (1 + 配股率) 還原，
並在個股卡上標示。ROE 是兩者的比值，不受攤薄影響。

**已知限制**：同日又配股又配息的「權息」，公開資料無法把配股率與現金股利分離，
這種情況只提示不修正；`bands.json` 的歷史序列同樣帶有配股斷層，配股頻繁的公司
「近 5 年區間」會比實際略寬。

### 關於「當天最新」

交易所的估價資料是**盤後**公布的（收盤 13:30，資料約 14:30 後齊全），
所以本站顯示的是最近一個交易日的收盤資料，不是盤中即時報價。
頁面右上角一律標示實際的資料日期。

網站上的「更新資料」按鈕可以**當場**再向交易所抓一次，不必等隔天的排程。
由於交易所的 API 沒有開放 CORS，瀏覽器無法直連，這個按鈕會透過公共 CORS 代理轉一手；
代理有時會失敗，此時頁面會明白告訴你哪個市場沒更新，並繼續沿用每日排程抓到的資料。
**每日排程是主要的資料來源**（在 GitHub 伺服器上執行，不受 CORS 限制），這顆按鈕只是加值。

## 三、八種估價法

每種方法都會算出「便宜價 / 合理價 / 昂貴價」三個價位。倍數優先採用**該股自己近 5 年的
歷史區間**（第 20／50／80 百分位），沒有歷史資料時才改用可自行調整的固定倍數。

### 本益比法 —— 年化 EPS（Forward P/E）

交易所的本益比用的是近四季 EPS，反映過去一整年。這個方法改用最新一期季報的
當年度累計每股盈餘年化：

```
年化 EPS = 當年度累計 EPS ÷ 季別 × 4
合理價   = 年化 EPS × 合理本益比
```

Q1 ×4、Q2 ×2、Q3 ×4/3、Q4 ×1。季數越少外推成分越重，卡片會標明用幾季推算。
季報 EPS 同樣會套用配股攤薄修正。

各公司申報時間不同，所以**每檔股票用的季別不一樣**，卡片標籤會直接寫
`年化 · 115Q2` 或 `年化 · 115Q1`。交易所 OpenAPI 只提供最新一期（季報剛開始
申報時涵蓋率僅三成），因此 `scripts/fetch_quarterly.py` 再用公開資訊觀測站
`t163sb04` 逐季回補：先抓舊季別、再讓新的覆蓋，每檔保留自己最新的一期。
目前涵蓋 1,955 檔的 100%。

近四季虧損的公司交易所不提供本益比，近四季本益比法無解；但若今年已轉盈，
這個年化法仍算得出來（實測有 97 檔屬於這種情況）。

### 月營收動能法

台股規定每月 10 日前公布上月營收，比季報快約 35 天，是最即時的基本面資料。

```
推估年營收 = 當年累計營收 ÷ 已過月數 × 12
推估年 EPS = 推估年營收 × (季報累計 EPS ÷ 季報累計營收)
合理價     = 推估年 EPS × 合理本益比
```

括號那項是「每一元營收貢獻多少每股盈餘」，由季報反推，不必查股數。
前提是淨利率穩定；金融保險業沒有可比的營收概念，不適用。涵蓋 1,469 檔（75%）。

以台積電為例，三種獲利推估的差異：近四季 EPS 74.38、季報年化 88.32、
月營收推估 95.86（累計營收年增 37%）。聯發科則因營收年增僅 0.8%，
三者落在 60.55～60.88，互為交叉驗證。

### PEG 本益成長比

```
PEG    = 本益比 ÷ 盈餘成長率(%)
合理價 = 預估今年 EPS × 成長率(%) × 目標 PEG
```

以 PEG = 1 為合理。成長率取「預估今年 EPS ÷ 去年全年 EPS − 1」，
並設上限（預設 40%）避免基期過低時算出離譜的目標本益比。
去年虧損或今年衰退時不適用。涵蓋 1,343 檔（69%）。

### ROE 法

由高登成長模型推導出公司「淨值該值幾倍」：

```
合理股價淨值比 = (ROE − g) ÷ (r − g)
合理價 = 每股淨值 × 合理股價淨值比
便宜價 / 昂貴價 = 合理價 × (1 ∓ 安全邊際)
```

`r` 是你要求的年報酬率（預設 8%），`g` 是長期成長率（預設 2%），安全邊際預設 25%。
ROE 必須大於 g，否則模型無解，網站會標示不適用。

### 股價淨值比法（P/B）

```
合理價 = 每股淨值 × 合理股價淨值比
```

適合資產型、獲利波動大的公司（金融、營建、景氣循環股）。

### 股價營收比（P/S）

營收恆為正，所以獲利尚未轉正的公司也估得出來 —— 這是其他獲利類方法完全無解的族群。

```
每股營收 = 推估年營收 × (季報 EPS ÷ 季報淨利)
合理價   = 每股營收 × 合理股價營收比
```

括號那項等於 1 ÷ 股數（虧損時分子分母同號仍為正），不必另外查股本。

**預設不納入綜合評估**：合理倍數因產業差異極大（軟體與 IC 設計 5~10 倍、
通路與代工可能低於 0.5 倍），沒有通用預設值，用一組固定值套全市場只會
污染綜合中位數。請依同業調整參數後再勾選。

涵蓋 1,742 檔（89%）。原本只剩股價淨值比法可用的 357 檔虧損股中，
有 331 檔因此多了一個估價依據。

### 股利法

```
合理價 = 每股現金股利 ÷ 目標殖利率
```

殖利率越高代表股價越便宜，所以便宜價用**最高**的殖利率去除。
固定倍數的預設值（6.25% / 5% / 3.125%）即經典的「股利 16 / 20 / 32 倍」。
適合配息穩定的成熟公司。

### 本益比法 —— 近四季 EPS（Trailing P/E）

```
近四季 EPS = 收盤價 ÷ 交易所本益比
合理價     = 近四季 EPS × 合理本益比
```

用已實現的一整年獲利，不做任何外推，比年化版保守穩定。
虧損的公司（交易所不提供本益比）會標示不適用。

### 綜合評估

取所有「可用且已勾選」方法的**中位數**（比平均數不容易被單一極端值拉走），
再和現價比對出位階。每張方法卡片都可以取消勾選，把不適合這家公司的方法排除掉。

## 四、本機執行

網站會用 `fetch()` 讀取 `data/*.json`，直接用 `file://` 開啟 `index.html` 會被瀏覽器擋下，
需要起一個本機伺服器：

```bash
python3 scripts/serve.py
```

然後開 <http://localhost:8899>。

手動更新資料：

```bash
python3 scripts/fetch_data.py
```

收集除權配股事件、季報與月營收（每日累積）：

```bash
python3 scripts/fetch_exrights.py && python3 scripts/fetch_quarterly.py && python3 scripts/fetch_revenue.py
```

重建近 5 年評價區間（約 180 次請求、5 分鐘）：

```bash
python3 scripts/build_bands.py --years 5
```

所有腳本都只用 Python 標準庫，不需要安裝任何套件。
