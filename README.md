# 幾塊你要買？

台股與美股的**財務計算工具箱**。對公開財務數字執行使用者指定的四則運算並顯示結果，
資料每個交易日自動抓取：台股取自臺灣證券交易所、證券櫃檯買賣中心與公開資訊觀測站，
美股取自 SEC EDGAR 與那斯達克。純靜態網站，可直接放在 GitHub Pages 上。

## 四個頁面

| 頁面 | 標的 | 內容 |
| --- | --- | --- |
| `index.html` 計算版 | 台股個股 | 九種公式，中性用語，只呈現「參數 → 對應價」 |
| `pro.html` 專業版 | 台股個股 | 同一套公式，整合成便宜／合理／昂貴三個價位 |
| `etf.html` ETF | 台股 ETF | 不做估價，只算折溢價（ETF 沒有財報） |
| `us.html` 美股 | 美股個股 | 九種公式套在美國市場，資料來源與制度不同處另有說明 |

四頁都有**中英文介面**，右上角可隨時切換，選擇記在 localStorage、跨頁共用。

## 中英切換怎麼做的

刻意分成兩條路，因為靜態文字與程式產生的文字性質不同：

**HTML 裡的靜態文字** —— 中英兩份都寫在原始碼裡，用 CSS 決定顯示哪一份：

```html
<span data-en="Close">收盤價</span>                     <!-- 短標籤 -->
<p class="i18n-zh">中文…</p><p class="i18n-en">English…</p>  <!-- 長段落 -->
<input placeholder="輸入…" data-ph-en="Search…">          <!-- 屬性 -->
```

翻譯就放在原文旁邊，改中文時看得到英文還沒跟上，不容易長期失同步。
CSS 預設把 `.i18n-en` 藏起來，所以 JS 沒跑或掛掉時最壞情況是看到中文，
而不是中英一起冒出來。

**程式產生的文字**（公式推導、不適用原因、彙總敘述）—— 那些字串帶變數，
沒辦法預先寫死，所以各頁 script 自己維護一份 `MSG` 字典，每則訊息是一個函式，
兩種語言各一份：

```js
fwdFormula: (ytd, n, eps, l, m, h, mult, risk) =>
  `年化 EPS ＝ 本年度累計 ${fmt(ytd)} ÷ ${n} 季 × 4 ＝ ${fmt(eps)} 美元…`
```

切換時發 `langchange` 事件，各頁重畫程式產生的部分。

幾個容易忽略的細節：**金額與數量要分開處理**（英文的金額前面要加 `$`、股數不能加）；
**中文的億／兆與英文的 B／T 進位不同**（1e8 vs 1e9），不能只換單位字；
`<title>` 與 `meta description` 也要跟著換。

**不翻的東西**：台股個股與 ETF 的中文名稱是公司／投信登記的正式名稱，
沒有官方英譯，一律維持原文；分類標籤（上市／上櫃、原型／債券／槓桿等）
只有固定幾種，則有對照表。

## 台股的兩個版本

同一個 repo 部署出兩個頁面，**公式、資料與參數完全共用**（同一份 `app.js`，
靠 `<body data-mode>` 切換呈現），差別只在輸出方式：

| | 計算版 `index.html` | 專業版 `pro.html` |
| --- | --- | --- |
| 三欄標題 | 參數本身（`15.94 倍`） | 便宜價／合理價／昂貴價 |
| 配色 | 中性藍階，只表示數值大小 | 綠／黃／紅位階 |
| 彙總 | 敘述統計（最小／中位／最大、百分位） | 三個價位 + 位階判定 |
| 進場條件 | 無 | 有，規則寫在畫面上 |

另有 **ETF 頁 `etf.html`** 與 **美股頁 `us.html`**（都見下），四頁在上方可互相切換。

**計算版的設計原則**：所有倍數、成長率、目標殖利率等假設一律由使用者設定；
本站不替任何個股設定價位、不對計算結果作評價、不推介標的、不提供買賣時點。
輸出一律以「參數 → 對應價」的形式呈現（例如「本益比 15.94 倍 → 1,185 元」），
而非「便宜／合理／昂貴」這類帶有判斷的說法。

**十一種公式**，依計算基礎分組：

- **本益比家族**：年化 EPS ｜ 近四季 EPS ｜ PEG ｜ 月營收動能 ｜ 葛拉漢公式
- **上限類**：葛拉漢數字（本益比 × 股價淨值比 的聯合上限，不含成長假設）
- **現金流類**：股價營業現金流比（P/OCF）
- **淨值類**：ROE 法 ｜ 股價淨值比（P/B）
- **營收類**：股價營收比（P/S）
- **股利類**：股利法

**葛拉漢公式與葛拉漢數字是兩個不同的東西**，卡片標籤與說明都刻意分開：
公式 `V = EPS × (8.5 + 2g)` 是**估值**，吃使用者輸入的成長率 g；
數字 `V = √(本益比 × 股價淨值比 × EPS × 每股淨值)` 是**上限**，不含任何成長假設，
把葛拉漢那兩條門檻（本益比 ≤ 15、股價淨值比 ≤ 1.5）合併成對乘積的單一限制。
本站不寫死 22.5，直接沿用使用者設定的三組倍數配對相乘 —— 設成 15 與 1.5
就回到原始版本。

**P/OCF 用的是營業現金流，不是自由現金流**：公開資訊觀測站的彙總現金流量表
只有營業、投資、籌資三大活動的合計，**沒有資本支出、也沒有折舊攤銷**，
所以台股做不出美股頁那種自由現金流。差別在說明區與卡片警語都寫明。

## ETF 為什麼獨立一頁

ETF 是一籃子證券、**沒有財報** —— 沒有 EPS、營收、淨利、ROE 與成長率，
所以上面九種公式有七種完全不適用，剩下兩種也要重新理解：

| 公式 | ETF | |
| --- | --- | --- |
| 本益比（年化／近四季）、PEG、月營收動能、葛拉漢、ROE、P/S | ✗ | 沒有對應的財報數字 |
| 股價淨值比 | △ | 算得出來，但意義完全不同 |
| 股利法 | ✓ | 配息型 ETF 適用 |

那個「△」是關鍵：個股的股價淨值比是估值指標，1.2 倍與 5 倍代表不同貴賤；
但 ETF 的淨值就是它持有那籃子證券的市值總和，**理論上市價應恆等於淨值**。
偏離不叫便宜或貴，那叫**折溢價**，屬於造市、流動性與申購贖回機制的問題。

因此 `etf.html` 不做估價，只呈現可客觀計算的折溢價：

```
折溢價率 = (收盤價 − 預估淨值) ÷ 預估淨值 × 100%
```

收錄 351 檔（上市 232、上櫃 119），並列出全市場溢價最高與折價最深的排行。
淨值取自證交所即時資訊系統彙整的各投信預估值（需帶 Referer），
非官方收盤淨值。內扣費用、追蹤誤差這些同樣重要的指標交易所沒有提供，
頁面上有註明要另外查詢。

## 美股頁 `us.html`

公式是同一套財務教科書內容，兩地通用。真正的差別在於**兩個市場公開的東西不一樣**，
所以有三處是被資料逼出來的差異，不是實作偷懶。收錄 5,580 檔在紐約證交所、
那斯達克與 CBOE 掛牌的普通股。

### 一、每股數字的方向相反

台灣的交易所**每天直接公布**每一檔的本益比、股價淨值比與現金殖利率，
台股版是「由比率反推每股數字」。美國沒有這種官方統計 —— SEC 只收財報、
交易所只有價格，所以美股版反過來：

```
股數     = 市值 ÷ 股價                    （那斯達克）
EPS      = SEC 申報的稀釋後每股盈餘        （近四季，重建，見下）
每股淨值 = 股東權益 ÷ 股數                 （SEC）
每股營收 = 近四季營收 ÷ 股數               （SEC）
ROE      = 近四季淨利 ÷ 股東權益           （SEC）
本益比   = 股價 ÷ 近四季 EPS
```

股數用「市值 ÷ 股價」而不是直接取財報的在外流通股數，是為了處理**雙重股權**：
波克夏 A 股與 B 股價格相差 1,500 倍，這樣算出來的兩邊會自動換算成一致的口徑
（實測 BRK-A 1.4708M 股、BRK-B 2.2063B 股，比值正好 1500）。
若公司申報的每股盈餘與這個股數對不起來（差距超過兩倍，多見於只申報單一股別的
雙重股權公司），改用「近四季淨利 ÷ 股數」，並在卡片上標示。

### 二、近四季（TTM）必須重建

XBRL 有個結構性缺口：公司的會計年度**第四季通常不會單獨標記** —— 年報只揭露
全年數字，Q4 要用「全年 − 前三季」才推得出來。實測 SEC 的日曆季彙總表：

```
EarningsPerShareDiluted 各期間的公司家數
  CY2025Q1  4,783      CY2025Q3  4,429
  CY2025Q2  4,726      CY2025Q4    944   ← 大部分公司的會計年度第四季
```

直接把四個日曆季相加，大部分公司會少一季。所以改用會計年度重建：

```
近四季 = 最近完整會計年度
       + 該年度結束後的累計
       − 去年同期累計
```

frames API 會把各公司的年報對應到最接近的日曆年標籤，所以年度值可以直接取用
（蘋果 2024-09-29～2025-09-27、輝達 2025-01-27～2026-01-25 都落在 `CY2025`）；
「年度結束後的季別」則由結束日推算並容忍 45 天，避免把年度內的最後一季重複計入。
以蘋果為例：FY2025 每股 7.46 ＋ 2026 前三季 6.87 − 2025 同期 ＝ **近四季 8.71**。

去年同期的季別若不齊、無法完成扣減，退回直接採用該會計年度的全年數字，
並在個股卡上標示。

### 三、沒有「近 5 年區間」，改用「同業當前分布」

台股版的三組倍數優先帶入**該股自己近 5 年**的 P20／P50／P80 —— 那是這一檔股票
自己被市場交易出來的歷史紀錄。美股要做到同一件事得逐檔抓五年股價（幾千次請求），
沒有等量的免費來源。

所以改用另一種同樣客觀、但**意義不同**的統計：**同產業所有個股「當前」的
P20／P50／P80**（本益比、股價淨值比、股價營收比、P/FCF、殖利率）。

| | 是什麼 |
| --- | --- |
| 台股「近 5 年區間」 | 這檔股票自己的歷史（跨時間） |
| 美股「同業當前分布」 | 此刻整個產業的樣子（跨公司） |

差別必須講清楚：同業分布**會跟著整個產業一起漲跌**。產業整體在高檔時中位數也在
高檔，它不告訴你「這個產業現在貴不貴」，只告訴你「這檔在同業裡站在哪個位置」。
產業分類取自那斯達克，樣本少於 12 檔的產業不計算分位數；統計時排除本益比 200 倍
以上、殖利率 25% 以上等極端值，避免一次性損益污染分位數（個股頁仍照實顯示）。

### 四、月營收動能法換成自由現金流法

台灣規定每月 10 日前公布上月營收，比季報快約 35 天 —— 台股版月營收動能法的
價值整個建立在這個「快」上。**美國沒有月營收制度**，只有季報。

硬做一個「季營收動能法」推導後會發現它和年化 EPS **完全相同**，季數在分子分母
消掉了，等於同一個數字算兩次：

```
推估年營收 × (累計EPS ÷ 累計營收)
  = (累計營收 ÷ n季 × 4) × (累計EPS ÷ 累計營收)
  = 累計EPS ÷ n季 × 4        ← 就是年化 EPS
```

所以那一格改放美股拿得到、其他八種公式都看不到的東西 —— **自由現金流**：

```
自由現金流     = 營業活動現金流 − 資本支出
每股自由現金流 = 自由現金流 ÷ 股數
對應價         = 每股自由現金流 × 你設定的 P/FCF 倍數
```

現金流量表在美國是以**年初至今累計**申報，而 frames 只建立 3 個月與 12 個月的
期間，半年與九個月的累計值不在任何 frame 裡，所以近四季無法穩定重建 ——
只取**最近一個完整會計年度**，比其他公式舊，卡片上標明期間。銀行與保險公司的
現金流量表結構不同，沒有可比的資本支出科目，會標示不適用。

### 已知限制

**外國發行人（ADR）沒有財報資料。**台積電（TSM）、艾司摩爾（ASML）、豐田（TM）
這類外國企業依 20-F 用 **IFRS 及當地幣別**申報，不在 SEC 的 us-gaap 彙總表內
（`ifrs-full` 沒有 frames 端點，實測回 404）。要換算成美元的每股數字還需要匯率
與 ADR 兌換比例（1 單位 ADR ≠ 1 股原股），這兩項沒有可靠的免費來源。
**與其算出一個看起來合理卻是錯的數字，本站選擇不算** —— 查詢這類股票時
頁面會直接說明原因，台積電則導向台股版的 2330。

5,580 檔中有 1,115 檔查不到 us-gaap 財報，其中 422 檔是外國註冊，
其餘多為新上市、SPAC、空殼公司，或公司重組後換了申報主體
（例如 XOM 的代號現已指向重組後的新 CIK，歷史財報留在舊主體）。

**庫藏股會壓低淨值。**美股大量實施庫藏股，買回的股份直接沖減股東權益，
長期買回的公司帳面淨值偏低、股價淨值比與 ROE 因而偏高，極端者股東權益為負
（如 MO），股價淨值比法與 ROE 法會直接標示不適用。這不是資料錯誤，
是這兩個公式碰到了它們的邊界。

**資料日期會落後一天。**每日排程在台北 15:20 執行，此時美股尚未開盤，
所以抓到的是前一個美股交易日的收盤價。頁面右上角一律標示實際的資料日期。

## 一、放上 GitHub 並開站

### 1. 建立 GitHub repo

到 <https://github.com/new> 建一個 repo。**名稱請用英文**（例如 `stock`），
中文名稱在網址上會被編碼成亂碼。可以是 Public 或 Private，兩者都能開 Pages。
不要勾選 "Add a README file"。

### 2. 推上去

在專案資料夾執行（把網址換成你自己的 repo）：

```bash
git remote add origin https://github.com/<你的帳號>/stock.git && git branch -M main && git push -u origin main
```

### 3. 開啟 GitHub Pages

到 repo 的 **Settings → Pages**，把 **Source** 選成 **GitHub Actions**（不是 Deploy from a branch）。

### 4. 給 Actions 寫入權限

到 **Settings → Actions → General**，捲到最下面的 **Workflow permissions**，
選 **Read and write permissions** 後按 Save。

這一步是必要的：每天更新完股價資料後，workflow 需要把 `data/` 的結果 commit 回 repo。

### 5. 跑第一次

到 **Actions** 分頁 → 左邊選「更新股價資料並部署」→ 右邊 **Run workflow**。
第一次可以勾選 `rebuild_bands` 一併重建近 5 年評價區間（約 5 分鐘）。

跑完後網站就在：

```
https://<你的帳號>.github.io/stock/
```

之後每個交易日 **台北時間 15:20** 會自動更新資料並重新部署，不需要再手動操作。

| 季報累計每股盈餘／營收／淨利 | 證交所、櫃買中心、公開資訊觀測站 | 每交易日累積 |
| 每月營業收入 | 證交所 `t187ap05_L`、櫃買中心 | 每交易日 |
| 在外流通股數、實收資本額 | 證交所 `t187ap03_L`、櫃買中心 `mopsfin_t187ap03_O` | 每交易日 |
| 季度營業活動現金流 | 公開資訊觀測站 `t163sb20` | 每交易日累積 |
| ETF 預估淨值 | 證交所即時系統 `all_etf.txt` | 每交易日 |
| 美股財報（EPS／營收／淨利／股東權益／現金流／股利） | SEC EDGAR XBRL frames API | 每交易日 |
| 美股收盤價、市值、產業別 | 那斯達克選股器 `api.nasdaq.com/api/screener/stocks` | 每交易日 |

美股的部分見上面的「[美股頁 `us.html`](#美股頁-ushtml)」。SEC 的 frames API
一次回傳「全體申報公司」在某個期間的某個會計科目，所以整個市場的季報與年報
只要幾十次請求就抓得完，不必逐檔查詢（實測全流程約 70 秒）；
依 SEC 規定，`User-Agent` 必須帶可聯絡的識別資訊。

以下是台股的部分。計算需要的每股數字，都由上面四個公開數字推算：

```
每股盈餘 EPS  = 收盤價 ÷ 本益比          （近四季）
每股淨值 BVPS = 收盤價 ÷ 股價淨值比       （最近一季）
股東權益報酬率 ROE = EPS ÷ BVPS = 股價淨值比 ÷ 本益比
每股現金股利 DPS = 收盤價 × 現金殖利率     （近一年）
```

### 在外流通股數與市值

估價公式其實用不到股數 —— 台股的每股數字全部由交易所公布的比率除得出來。
但市值與股本是理解公司規模的基本資訊，台股又習慣用股本大小分類個股，
所以另外抓一次公司基本資料：

```
上市  t187ap03_L 直接給「已發行普通股數」（涵蓋 1,089 檔）
上櫃  只給實收資本額與面額，股數 = 實收資本額 ÷ 面額（涵蓋 889 檔）
市值  = 收盤價 × 在外流通股數
```

**上市那支 API 在雲端會被擋。**`openapi.twse.com.tw` 對 GitHub Actions 的 IP
回傳非 JSON（本機正常，CI 拿到 0 檔），所以股數與資本額有一段
**沿用上一次的值**的備援 —— 這兩個數字只在增資、減資、配股時才變動，
用昨天的遠比整欄留空好。實測備援可救回 1,079 檔。

**面額不能寫死 10 元。**2014 年放寬彈性面額後，市場上有 5 元、2.5 元、1 元、
0.5 元的個股，外國企業（F 股、KY 股）甚至以美元計價 —— 用美元面額去除新台幣
資本額會錯一個匯率，所以這種情況寧可留空（目前 1 檔）。

也試過用「累計淨利 ÷ 累計每股盈餘」反推股數（這兩個數字季報都有），
台積電、聯發科等大型股誤差在 0.5% 以內，但有 **91 檔差超過 10%** ——
因為季報的淨利是**合併淨利（含非控制權益）**，而每股盈餘的分子是
**歸屬母公司普通股股東的淨利**，有子公司少數股權的控股型公司兩者差很多。
所以最後採用交易所的官方股數，不用反推。

另外注意 **股本與股數不是簡單的 10 倍關係**：實收資本額含特別股，
在外流通股數只算普通股。國泰金 2882 股本 1,620 億、普通股 146.7 億股，
相除得到 11.05 而非 10，差額就是特別股。

### 除權配股的攤薄修正

交易所公布的本益比與股價淨值比，在除權當天是拿**已經稀釋的股價**除以**還沒按新股本
重算的每股盈餘**。實測倫飛 2364、華友聯 1436、豐藝 6189，除權日的本益比與股價淨值比
都隨股價跳空 20~30%，而反推出的每股盈餘一動也沒動：

```
倫飛 2364  8/27 → 8/28（除權配股 30%）
  收盤價   99.30 → 77.50   (−22.0%)
  本益比   24.95 → 19.47   (−22.0%)   ← 跟著股價跳空
  推算 EPS  3.98 →  3.98   (不變)     ← 沒有攤薄
```

交易所在除權息預告表裡揭露的「申報每股淨值」也證實了這點：根基 2546 於 2026-08-10
配股 12%，申報每股淨值仍是 50.33（未攤薄），而非 44.94。

若直接採用，本益比法、股價淨值比法、ROE 法算出的對應價會一併高估，幅度約等於配股率，
並持續到下一次財報更新。因此 `scripts/fetch_exrights.py` 每天累積配股事件，前端對
「除權日晚於財報基準季季末」的個股，把 EPS 與每股淨值除以 (1 + 配股率) 還原，
並在個股卡上標示。ROE 是兩者的比值，不受攤薄影響。

**已知限制**：同日又配股又配息的「權息」，公開資料無法把配股率與現金股利分離，
這種情況只提示不修正；`bands.json` 的歷史序列同樣帶有配股斷層，配股頻繁的公司
「近 5 年區間」會比實際略寬。

### 關於「當天最新」

交易所的估價資料是**盤後**公布的（收盤 13:30，資料約 14:30 後齊全），
所以本站顯示的是最近一個交易日的收盤資料，不是盤中即時報價。
頁面右上角一律標示實際的資料日期。

網站上的「更新資料」按鈕可以**當場**再向交易所抓一次，不必等隔天的排程。
由於交易所的 API 沒有開放 CORS，瀏覽器無法直連，這個按鈕會透過公共 CORS 代理轉一手；
代理有時會失敗，此時頁面會明白告訴你哪個市場沒更新，並繼續沿用每日排程抓到的資料。
**每日排程是主要的資料來源**（在 GitHub 伺服器上執行，不受 CORS 限制），這顆按鈕只是加值。

## 三、九種計算公式

每個公式都用「低 / 中 / 高」三組參數各算一次，卡片標題直接顯示**參數本身**
（例如「15.94 倍 / 23.45 倍 / 27.90 倍」），下方是對應的價格 —— 純粹是參數到結果的映射。

三組參數預設帶入**該股自己近 5 年的實際成交統計**（本益比、股價淨值比、殖利率的
第 20／50／80 百分位），這是客觀的歷史紀錄而非建議值；沒有歷史資料時改用你在
「計算參數」中自訂的倍數。任何一個數字你都可以覆寫。

### 自訂每股盈餘

參數區可直接填入你自己預估的年度 EPS。填了之後，所有以預估 EPS 為基礎的公式
（年化本益比、月營收動能、本益成長比、葛拉漢公式）一律改用你的數字，
卡片會標示「你輸入的 EPS」；留空則沿用本站依季報與月營收算出的值。

### 本益比法 —— 年化 EPS（Forward P/E）

交易所的本益比用的是近四季 EPS，反映過去一整年。這個方法改用最新一期季報的
當年度累計每股盈餘年化：

```
年化 EPS = 當年度累計 EPS ÷ 季別 × 4
對應價   = 年化 EPS × 你設定的本益比倍數
```

Q1 ×4、Q2 ×2、Q3 ×4/3、Q4 ×1。季數越少外推成分越重，卡片會標明用幾季推算。
季報 EPS 同樣會套用配股攤薄修正。

各公司申報時間不同，所以**每檔股票用的季別不一樣**，卡片標籤會直接寫
`年化 · 115Q2` 或 `年化 · 115Q1`。交易所 OpenAPI 只提供最新一期（季報剛開始
申報時涵蓋率僅三成），因此 `scripts/fetch_quarterly.py` 再用公開資訊觀測站
`t163sb04` 逐季回補：先抓舊季別、再讓新的覆蓋，每檔保留自己最新的一期。
目前涵蓋 1,955 檔的 100%。

近四季虧損的公司交易所不提供本益比，近四季本益比法無解；但若今年已轉盈，
這個年化法仍算得出來（實測有 97 檔屬於這種情況）。

### 本益比法 —— 近四季 EPS（Trailing P/E）

```
近四季 EPS = 收盤價 ÷ 交易所本益比
對應價     = 近四季 EPS × 你設定的本益比倍數
```

用已實現的一整年獲利，不做任何外推，是上面年化版的保守對照組。
虧損的公司（交易所不提供本益比）會標示不適用。

### PEG 本益成長比

```
PEG    = 本益比 ÷ 盈餘成長率(%)
對應價 = 預估今年 EPS × 成長率(%) × 你設定的目標 PEG
```

文獻上常以 PEG = 1 作為對照基準，三組目標值由你設定。成長率取「預估今年 EPS ÷ 去年全年 EPS − 1」，
並設上限（預設 40%）避免基期過低時算出極端的倍數。
去年虧損或今年衰退時不適用。涵蓋 1,343 檔（69%）。

### 月營收動能法

台股規定每月 10 日前公布上月營收，比季報快約 35 天，是最即時的基本面資料。

```
推估年營收 = 當年累計營收 ÷ 已過月數 × 12
推估年 EPS = 推估年營收 × (季報累計 EPS ÷ 季報累計營收)
對應價     = 推估年 EPS × 你設定的本益比倍數
```

括號那項是「每一元營收貢獻多少每股盈餘」，由季報反推，不必查股數。
前提是淨利率穩定；金融保險業沒有可比的營收概念，不適用。涵蓋 1,469 檔（75%）。

以台積電為例，三種獲利推估的差異：近四季 EPS 74.38、季報年化 88.32、
月營收推估 95.86（累計營收年增 37%）。聯發科則因營收年增僅 0.8%，
三者落在 60.55～60.88，互為交叉驗證。

### 葛拉漢公式

出自葛拉漢《The Intelligent Investor》修訂版所載的簡化算式：

```
V = EPS × (8.5 + 2g)
```

`8.5` 是葛拉漢 1962 年觀察到「零成長公司」的基準本益比，`g` 為預期年成長率（%）。
**本站不替任何個股預設 g**，完全由使用者在參數區輸入，卡片同時列出 g ± 敏感度
三組結果以顯示假設變動的影響。

此式是 1960 年代的經驗公式，未考慮利率環境（原著另有以 AAA 公司債殖利率調整的版本），
對高成長股會給出很高的倍數。

### ROE 法

由高登成長模型推導出公司「淨值該值幾倍」：

```
模型股價淨值比 = (ROE − g) ÷ (r − g)
對應價 = 每股淨值 × 模型股價淨值比
上下限 = 對應價 × (1 ∓ 你設定的安全邊際)
```

`r` 是你要求的年報酬率（預設 8%），`g` 是長期成長率（預設 2%），安全邊際預設 25%。
ROE 必須大於 g，否則模型無解，網站會標示不適用。

### 股價淨值比法（P/B）

```
對應價 = 每股淨值 × 你選定的股價淨值比倍數
```

適合資產型、獲利波動大的公司（金融、營建、景氣循環股）。

### 股價營收比（P/S）

營收恆為正，所以獲利尚未轉正的公司也估得出來 —— 這是其他獲利類方法完全無解的族群。

```
每股營收 = 推估年營收 × (季報 EPS ÷ 季報淨利)
對應價   = 每股營收 × 你選定的股價營收比倍數
```

括號那項等於 1 ÷ 股數（虧損時分子分母同號仍為正），不必另外查股本。

**預設不納入彙總統計**：適用倍數因產業差異極大（軟體與 IC 設計 5~10 倍、
通路與代工可能低於 0.5 倍），沒有通用預設值，用一組固定值套全市場只會
扭曲統計量。請依同業設定參數後再勾選納入。

涵蓋 1,742 檔（89%）。原本只剩股價淨值比法可用的 357 檔虧損股中，
有 331 檔因此多了一個可計算的公式。

### 股利法

```
對應價 = 每股現金股利 ÷ 你設定的目標殖利率
```

殖利率與價格成反比，最高的目標殖利率對應最低的價格。
預設值 6.25% / 5% / 3.125% 即「股利 × 16 / 20 / 32 倍」的換算。
適合配息穩定的成熟公司。

### 獲利品質（毛利率／營業利益率）

個股卡下方另有一塊「獲利品質」，列出毛利率與營業利益率的走勢
（年度最多三期，加上最新一期）。

**它刻意不是第十二種公式，也不進彙總統計。**站上所有公式的分母幾乎都是
盈餘，這一塊回答的是另一個問題：那個盈餘的品質如何。特斯拉是最好的例子：

```
        營收(億)  毛利率   營業利益率    EPS
2023      968    18.2%      9.2%     4.30
2024      977    17.9%      7.2%     2.04
2025      948    18.0%      4.6%     1.08
```

營收幾乎沒動、毛利率也沒動，但**營業利益率從 9.2% 壓到 4.6%** —— EPS 就是
這樣掉了 75%。同一段期間存貨年增只有 −5.6%，完全看不出問題。

資料來源：台股沿用既有的 `fetch_quarterly.py`（公開資訊觀測站 `t163sb04`
本來就有「營業毛利（毛損）淨額」與「營業利益（損失）」兩欄，不必多發請求）；
美股新增 SEC `GrossProfit` 與 `OperatingIncomeLoss` 年度 frames。
涵蓋台股 1,931 / 1,975 檔、美股 3,150 / 5,580 檔 ——
**銀行、保險、金控沒有可比的營收與毛利概念，一律不顯示**。

毛利取「營業毛利（毛損）**淨額**」而非未沖銷的版本，因為前者已扣除
未實現／已實現銷貨損益，跨公司比較才一致。

### 為什麼不做「庫存」

庫存看似能判斷滯銷風險，實際上兩個問題：一是**台股拿不到**
（`t163sb01/05/06/07/15` 與證交所、櫃買的資產負債表都只給「流動資產」總額，
不拆存貨）；二是**就算拿得到，訊號會誤導**。實測美股「存貨成長 − 營收成長」
的背離：

```
AAPL 蘋果    存貨 +87.2%  營收  +6.4%   背離 +80.8pt   ← 會被標紅
NVDA 輝達    存貨 +111%   營收 +65.5%   背離 +45.6pt   ← 會被標紅
TSLA 特斯拉  存貨  −5.6%  營收  −2.9%   背離  −2.7pt   ← 完全不會被標
```

背離最嚴重的兩家都好好的（為新產品拉貨），而 EPS 真的掉了 75% 的那家
完全沒被標到。「存貨增加」本身是雙義的 —— 可能是有信心在拉產能，也可能是
賣不掉，一個數字分不出來。何況存貨已經算在股東權益裡，股價淨值比早就
涵蓋過一次，再拿來推股價是重複計算。

### 現價落在所有計算值之外時

獲利大幅衰退但股價還在高檔的公司（例如特斯拉近四季每股盈餘 1.08 美元、
本益比 323 倍），畫面上會出現一整排遠低於現價的數字，第一眼很像資料抓錯。
所以彙總區會在現價高於（或低於）**全部**計算值時，直接把落差最大的那個
比率指出來 —— 那就是所有公式一起偏離的同一個原因：

```
現價 348.75 美元高於全部 18 個計算值（最大值 129.36）。
落差主要來自本益比 322.92 倍，是同業中位數 27.96 倍的 11.5 倍。
```

主因是逐檔算出來的，不是寫死本益比：Palantir 會指向股價營收比（72.69 倍、
同業中位數的 24.5 倍），Coinbase 指向股價淨值比。現價低於全部計算值時
措辭會翻過來（「只有參考倍數的 1/6.6」）。

文字只陳述倍數關係，**不說貴或便宜** —— 計算值取決於使用者設定的倍數，
市價取決於市場願意付多少，兩邊都不必然是對的。

### 計算值彙總

把各公式在你設定的參數下算出的所有數值蒐集起來，做**敘述統計**：
最小值、中位數、最大值，以及現價落在這些數值中的相對位置（百分位）。

這一區**不對任何數值賦予評價**，也不推論該不該買賣 —— 參數是你選的，
結論也應該由你自己下。每張卡片都可以取消勾選，把不適用的公式排除。

## 四、本機執行

網站會用 `fetch()` 讀取 `data/*.json`，直接用 `file://` 開啟 `index.html` 會被瀏覽器擋下，
需要起一個本機伺服器：

```bash
python3 scripts/serve.py
```

然後開 <http://localhost:8899>。

手動更新資料：

```bash
python3 scripts/fetch_data.py
```

更新美股（SEC 財報 + 那斯達克收盤價，約 70 秒）：

```bash
python3 scripts/fetch_us.py
```

SEC 的存取規範要求 `User-Agent` 帶得到聯絡方式。程式不把 email 寫死在原始碼裡
（這是公開 repo，寫死等於把信箱送給爬蟲），改從環境變數讀：

```bash
SEC_CONTACT="you@example.com" python3 scripts/fetch_us.py
```

排程執行的話，到 repo 的 **Settings → Secrets and variables → Actions** 新增一個
名為 `SEC_CONTACT` 的 secret，workflow 已經把它帶進去了。不設也能跑
（實測 SEC 目前不會擋），只是流量是匿名的，對方要限流時沒辦法通知你。
另外 UA 裡**不能放網址**，SEC 的防護會直接回 403。

收集除權配股事件、季報與月營收（每日累積）：

```bash
python3 scripts/fetch_exrights.py && python3 scripts/fetch_quarterly.py && python3 scripts/fetch_revenue.py && python3 scripts/fetch_cashflow.py
```

重建近 5 年評價區間（約 180 次請求、5 分鐘）：

```bash
python3 scripts/build_bands.py --years 5
```

所有腳本都只用 Python 標準庫，不需要安裝任何套件。

## 瀏覽人次

頁尾有一個瀏覽人次計數，由 [hits.sh](https://hits.sh) 提供 —— 純靜態網站沒有後端，
自己記不了數，一定得靠外部服務。

**這是全站唯一一個對外送出資料的地方，值得說清楚。**站上其他所有東西都在你的
瀏覽器裡算完，`data/*.json` 讀進來之後不會再往外送任何東西。加上計數之後，
每次開啟頁面會向 hits.sh 請求一張徽章圖片，**該服務會看到你的 IP 與來源網址**。
所以頁尾的資料來源那段也加了一行揭露，四頁都有。

實作上有三個細節：

**不用 `loading="lazy"`。**徽章在頁尾，設成延遲載入的話，使用者沒捲到底就不會
發出請求，人次會大量漏記。

**徽章只顯示數字，「瀏覽人次」四個字是頁面自己的 HTML 文字。**因為標籤是寫在
圖片網址的參數裡的，如果連標籤一起做中英切換，切換語言就會換一次網址、
**多記一次人次**。把標籤拆出來之後圖片網址永遠不變。

**服務掛掉不留破圖。**`i18n.js` 對徽章掛了 `error` 監聽，載入失敗就把整塊隱藏。

計數的 key 是 `luckylongan.github.io/stock`，四頁共用，所以顯示的是全站總瀏覽次數
（不是不重複訪客）。開發時測過幾次，起始值不是 0。

想換成更完整的分析（不重複訪客、來源、熱門頁面），[GoatCounter](https://www.goatcounter.com)
與 Cloudflare Web Analytics 都是不用 Cookie 的選擇，但都需要註冊帳號。
